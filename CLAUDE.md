# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`eng` — the shared C++20 engine library for these games (currently used by `../delve`; `../arena` is meant to migrate onto it — its Vulkan core, crash log and Steam code were extracted from arena and kept API-compatible apart from the `eng` namespace). Static library.

## Building

zig only (`build.zig`); the toolchain comes from devenv (`devenv shell`, or direnv via the checked-in `.envrc`): zig, glslc (shaderc), pkg-config, and headers for Vulkan, GLM, X11, xkbcommon and Wayland, plus wayland-scanner. GLFW 3.4, Clay (a `main` commit; its last tag, v0.14, is from mid-2025) and Lua 5.4.8 are pinned in `build.zig.zon`; stb_truetype v1.28 is vendored in `third_party/`.

- `zig build` → `zig-out/lib/libeng.a` + headers. `-Dsteam=false` drops Steamworks. `zig build --watch -fincremental` (devenv `watch`) rebuilds on save; zig caches each C/C++ object by content, so only changed translation units recompile (and `touch` alone rebuilds nothing).
- **Targets:** native for development. Releases use `-Dtarget=x86_64-linux-gnu.2.31` (portable: standard loader, glibc ≥ 2.29 symbols, runs on any distro with glibc 2.31+) and `-Dtarget=x86_64-windows-gnu` (cross-compiled; UCRT + static libc++, no MinGW DLLs). Both with `-Dcpu=x86_64_v2`: a zig/clang baseline-x86-64 build runs the delve soak ~15% slower than GCC did, v2 matches it.
- **GLFW is built from source** as its own static lib (its sources reject the `GLFW_INCLUDE_NONE` that eng compiles with). On Linux it has both the X11 and Wayland backends, which `dlopen()` their libraries at runtime, so only their headers are needed at build time; the Wayland protocol headers are generated with wayland-scanner. It prefers native Wayland over XWayland.
- **Headers come from pkg-config** (`addPkgConfigIncludes`, also `pub` for games) for every target, native or not; zig's own native-path detection doesn't apply to cross targets. When pkg-config gives no `-I` (a normal distro's `/usr/include`, which it strips), it falls back to `--variable=includedir` and copies out only the package's own header subtrees (`pc_header_entries`): adding all of `/usr/include` would mix Linux libc headers into Windows/old-glibc builds. When pkg-config doesn't know the package at all (Arch's glm ships no `.pc`), it looks in the system include dirs (`PKG_CONFIG_SYSTEM_INCLUDE_PATH`, else `/usr/include:/usr/local/include`). Tested with a merged-include fake distro (no `glm.pc`) for native, glibc 2.31 and Windows, including `./build.sh`.
- **Vulkan:** on Linux, the game links the build machine's loader (`libvulkan.so`, else `libvulkan.so.1`) only for its soname. For explicit-glibc targets (`x86_64-linux-gnu.2.31`) it sets `linker_allow_shlib_undefined`, since that loader references newer glibc than the target has; native builds keep the check, so a real missing symbol (say after a libsteam_api.so update) still fails a dev build. On Windows, the import lib is generated by `zig dlltool` from `third_party/vulkan/vulkan-1.def` (from Vulkan-Loader, Apache-2.0). pkg-config/loader problems stop the build with an `eng:` message rather than a crash.
- **Consumers** do `b.dependency("eng", .{ .target, .optimize, .steam })`, then `@import("eng").link(b, exe, eng_dep)` and `installSteamRuntime(b, eng_dep, exe, appid)` (`$ORIGIN` rpath + Steam lib/appid copy; a no-op without Steam; returns its step for partial-install steps). Always go through `link`, never a bare `linkLibrary`: include paths and system libs propagate from the artifact, but C macros, library paths and prebuilt objects don't.
- **Build options that change headers live in the generated `eng/config.h`**, installed with the headers and included by the headers that need it. `ENG_HAVE_STEAM` changes `SteamPlatform`'s layout; when it was a per-module macro, a game built without it had the engine write past its smaller `SteamPlatform` and silently corrupt the stack (in delve, `leaveLobby()` zeroed `Game::m_effects`). Likewise `link()` reads whether Steam is in from the dependency (named lazy paths), not from the caller, so libeng and the game can't disagree. Option-independent public macros (`GLFW_INCLUDE_NONE`, Windows' `NOMINMAX`/`WIN32_LEAN_AND_MEAN`) are set by `link()`. Never define `_WIN32_WINNT`: zig predefines it from the target's minimum OS (Windows 10 by default, also Steam's minimum), and a second definition conflicts.
- On NixOS, a portable (old-glibc) Linux build runs through nix-ld but needs the devenv's `LD_LIBRARY_PATH` for libvulkan and the libraries GLFW dlopens — normal distros have them.

`zig build test` runs eng's own tests (`tests/script_test.cpp`: the Lua sandbox, limits, require, bytecode, hot reload — scripts in `tests/scripts/`, compiled by `eng-luac` first; `tests/ecs_test.cpp`: the ECS core; `tests/luaecs_test.cpp`: the Lua bridge; `tests/content_test.cpp`: packs, mods, prefabs, manifests; `tests/replication_test.cpp`: snapshots through a lossy channel, splitting, interpolation, fuzzed packets, and a UDP loopback run under `LagTransport` on a random port 47000–48999). Otherwise it's exercised through a game (`../delve`'s build, `delve_simtest`, and its `--screenshot` visual checks) and, for the UI layer, `zig build ui-demo` (`examples/ui_demo.cpp`; `-- --screenshot out.png` renders and quits, `-- --scale 1` pins the UI scale — a tiling window manager resizes the window, `-- --fonts dir` defaults to `../delve/Assets/Fonts`). Linux only; it resolves the Vulkan loader like `link()` does.

## Modules (all namespace `eng`, headers under `include/eng/`)

- `core/` — `CrashLog` (tees stdout/stderr to `<app>_log.txt`, catches signals/SEH/terminate; call `crashlog::init` first thing in main), `Log.h` (`ENG_LOG`).
- `platform/` — `Window` (GLFW, no-API, resize flag, fullscreen toggle), `Input` (per-frame key/mouse/gamepad snapshot with pressed/released edges; mouse in framebuffer pixels). Event-only input — typed text (codepoints), the scroll wheel, and key presses with OS auto-repeat (`keyTyped`) — comes from GLFW callbacks the `Window` registers in its constructor. `Input::update` drains them via the window's user pointer.
- `render/` — `VulkanContext`, `Swapchain` (now takes `srgb`/`depth` options; arena's defaults preserved), `VulkanUtils`, and `Renderer2D`:
  - Immediate-mode sprites (`draw(Sprite)`, `drawRect/Circle/Line`), drawn in submission order, batched by texture/blend/space. Builtin textures `kWhite`, `kCircle`.
  - `Space::World` (camera: center + pixels-per-unit, y-down) vs `Space::Screen` (pixels).
  - Textures get their descriptor sets from the renderer's own pool (one combined image sampler, binding 0, fragment; `allocateTextureSet`), freed with the pool — or individually for the lightmaps, which are recreated with the swapchain. (Dear ImGui used to supply these and draw on top; it was removed once Delve's UI moved to eng::ui.)
  - Shaders (`shaders/`) are compiled at build time with `glslc -mfmt=c` and embedded — no runtime shader files.
  - UNORM swapchain (not sRGB) so pixel-art and UI colors pass through untouched.
  - `beginFrame()` returns false while minimized instead of blocking — a host's simulation must keep ticking.
  - `requestScreenshot(path)` reads back the next presented frame to PNG (stb_image_write).
  - **eng::DrawList** (`DrawList.h`): immediate screen-space vector drawing shaped like ImGui's ImDrawList (ImGui-style code ports by renaming: `AddLine`→`line`, `IM_COL32`→`ENG_COL32`, `ImVec2`→`glm::vec2`; same argument order, minus ImGui's flag arguments). Lines, rects (rounded), multi-color rects, circles, rotated ellipses, triangles, quads, convex/concave polygons, Béziers, paths, text (with word wrap and a default font/size), images, clip rects. Anti-aliased like ImGui: a 1px fringe fading to transparent (`Renderer2D::drawTriangleColors`/`drawQuadColors` carry the per-vertex alpha); unrounded axis-aligned rect fills stay hard-edged; lines and outlined rects sit on pixel centers (+0.5); the fill fringe is oriented from the polygon's winding, so either winding works. Draws go into the sprite stream at call time.
  - **UI shapes** (`Shapes.cpp`): `drawRoundedRect` / `drawRoundedBorder` with per-corner radii (CSS-style clamp) and per-edge widths — triangle fans/rings on `kWhite`, not anti-aliased. **Clipping:** `pushClip(rect)` / `popClip()` (screen pixels, nested clips intersect) — each batch carries a clip index and `recordBatches` sets the scissor; the lightmap pass ignores clips.
  - **Text** (`Text.cpp`, private `Font.h`): `loadFont` (stb_truetype) → `drawText` / `measureText` / `fontMetrics`, in either space. Pixel size means ascent−descent, as in ImGui. Each (font, integer pixel size) bakes its own atlas on first use: Latin-1 + dashes/quotes/bullet/ellipsis, arrows, −≈≠≤≥, anything else draws `?`. Atlases are 2× horizontally oversampled and **bilinear** (`createTexture(..., linear=true)`; sprites stay nearest) so glyphs sit at fractional x — whole-pixel snapping per glyph made spaces vanish or double at ~11px; rows still snap to whole pixels. Kerning from GPOS/kern via stb.
  - Blend modes: Alpha, Additive, Modulate2x (dst × src × 2 — 0.5 grey is neutral). `drawTriangle` for fans/polygons (a quad with a degenerate second triangle, so it batches with sprites).
  - **Lighting**: a half-resolution, linearly-filtered lightmap (one per frame in flight, `R8G8B8A8_UNORM`, its own render pass recorded before the main one). `beginLights(ambient)` … `endLights()` routes every draw into the lightmap's batch list (same vertex buffer); `compositeLights()` puts a Modulate2x screen quad of it into the scene stream at that point, so what's drawn before is lit and what's after isn't. Frames that never composite skip the pass. The lightmap images are recreated with the swapchain; their texture slots keep their ids. Shadow geometry is the game's job (Delve: `client/Lighting.cpp`).
- `ui/` — **eng::ui** (`include/eng/ui/Ui.h`): Clay lays out, Renderer2D draws, a small widget layer adds interaction. Games include `<clay.h>` (installed with the headers; implementation compiled once as C99 in `src/ui/Clay.c`) and write `CLAY(id, {...})` between `ui::Context::begin(input, dt)` and `end()` (which draws on top of everything drawn so far that frame). Widgets: `text`, `button`, `checkbox`, `sliderFloat/Int`, `textField` (Ctrl+V paste, Backspace repeat), plus `ctx.scrollY()`, `ctx.image(tex, tint)`, `ctx.custom(fn)`, `ctx.str()/fmt()` (per-frame string arena — Clay keeps pointers until `end()`).
  - Interaction uses the *previous* frame's layout (Clay hit-tests on `Clay_SetPointerState`), like ImGui. `Context::interact(id)` registers a focusable in declaration order; arrows / Tab / d-pad / left stick (with repeat) move focus through that order (wrapping), Enter/Space/pad A activate, Escape/pad B → `backPressed()`. The focus ring only shows while keys/pad drive; mouse motion hides it. Focus moves scroll the innermost `scrollY()` container (found geometrically from last frame's boxes) to keep it visible. `wantsKeyboard()` while a text field edits — games should ignore gameplay keys then.
  - Clay quirks: C++20 designated initializers must follow declaration order (the order is listed in `Ui.h`); widgets fill `Clay_ElementDeclaration` field by field instead. Clay emits an element's `backgroundColor` RECTANGLE *after* its IMAGE, so image tint goes through `ctx.image(tex, tint)` (a per-frame table behind `imageData`), never `backgroundColor`. One Clay context per process. Overlay-color commands are ignored.
  - `begin(input, dt, navigation=false)` freezes keys/pad focus and activation for a frame (e.g. while a game waits for a key to rebind); `ui::tooltip(anchor, text)` floats a note under an element (passthrough, z 1000); `ctx.isHovered(id)` tests without registering a focusable.
- `script/` — **eng::Scripts** (Lua 5.4; plan and later phases in `docs/ecs-lua-plan.md`). One `lua_State` holding sandboxed environments: the base game, then one per mod (`addEnv(name, root, ScriptTrust::Base|Mod)`), each with its own globals, module cache and `require` root (a mod's `require` falls back to base modules — the same tables, so mods can patch them). Scripts get a safe subset of the stdlib: no `io`/`os`/`debug`/`package`/`dofile`/`loadfile`/`collectgarbage`/`string.dump`/`math.random` (games bind a deterministic RNG); `load` is text-only; `setmetatable` refuses `__gc` (finalizers run with hooks off, outside the limits). Base scripts load `.luac` bytecode when present (release) else `.lua`; mods are text only (malformed bytecode can corrupt memory). Limits per `ScriptLimits`: a custom allocator caps the state's memory; a count hook (every 1000 instructions) caps each top-level `call()` and re-raises through `pcall`/`xpcall`/coroutines so scripts can't swallow it — xpcall's message handler is skipped once the budget is spent, because Lua runs it inside the hook with hooks off (a looping handler hung `script_test` before that). `call()` logs errors with tracebacks; `reloadChanged()` re-runs modules whose files changed, updating module tables in place. Determinism: Lua is compiled **as C++** (errors are exceptions, so they unwind C++ frames in bindings — include `<lua/lua.h>`/`<lua/lauxlib.h>`, never `lua.hpp`) with `luai_makeseed` = 0, so string hashing and `pairs()` order over string/number keys match on every machine.
  - **Bytecode:** `eng-luac` (a host tool built from the same Lua sources) compiles a tree of `.lua` to `.luac`, keeping debug info and `@relative/path` chunk names; syntax errors fail the build. Games call `@import("eng").compileScripts(b, eng_dep, b.path("scripts"))` for the output directory. Bytecode depends on the Lua version and number/instruction sizes, identical on the x86_64 Linux and Windows targets.
- `ecs/` — the ECS (plan: `docs/ecs-lua-plan.md`). `Registry` describes components (reflected fields with net encoding; C++ types via `add<T>`, Lua/mod ones via `addSchema`; ids sorted by name at `finalize()`, plus a schema hash peers compare). `World` holds entities (`uint32`: 16-bit slot + generation, 0 = null; cap configurable up to 65535) in a sparse set per component, with prefabs (per-prefab caps), `each<Cs...>`/`query`, and `commands()` for structural changes while iterating (`flush()` between systems).
  - **`LuaEcs`** exposes it to scripts as read-only `ecs` and `events` globals (`Scripts::makeReadOnly`, so a mod can't replace `ecs.spawn` for everyone). Construct it before scripts declare components (`ecs.component(name, schema)` works only until `finalize()`), then `attach(&world)`. Entities are plain integers; `ecs.get(e, "Health")` returns a ref that reads and writes fields by reflection and re-resolves the entity on every access (an error, never a dangling pointer, once it's gone); vec2 fields are write-through refs. Integer fields are range-checked. Structural calls made while the world iterates (inside `ecs.each`) go to `commands()`, which the game flushes. `World`/`Registry` exceptions become Lua errors. Event handlers run in registration order and belong to the file that defines them: `Scripts::addReloadListener` lets the bridge drop a file's handlers before hot reload re-runs it.
  - **`Content`** loads scripted content: the base pack (`setBase(dir, version)`), then mods found by `discover(modsDir)` (each folder's `mod.lua`: `{id, version, name, requires}`, run with no globals) and enabled in the player's order (`enable`; unknown, repeated or missing-dependency mods are skipped). Stages, pack by pack: `declareComponents()` (`components.lua`, before `finalize()`), `loadPrefabs(world)` (`prefabs/**.lua`, one prefab per file named by its path — `prefabs/enemies/bat.lua` is `enemies/bat`; a later pack replaces it, or with `patch = true` sets only the fields it names, `Comp = false` removing a component), `runInit()` (`init.lua`). Prefabs are defined sorted by name so PrefabIds match across peers. Errors are logged and kept in `errors()`; a pack whose `components.lua`/`init.lua` fails is marked failed and skips later stages, a bad prefab file skips just that prefab. `manifest()` (packs in order with version and `hashDirectory` of every file, plus the schema hash) goes over the wire with `ByteWriter`; `diff(host)` gives the reasons a join is refused.
  - **Replication** (`Replication.h`): `SnapshotServer::capture(world, tick)` each tick, `encode(clientAckTick)` → packets (≤ `maxPacketBytes`, default 1200; send unreliable) delta-encoded against a snapshot the client acknowledged (last `history` = 32 kept), else full. `SnapshotClient::receive(bytes)` (needs every part of a tick; malformed packets are rejected untouched), `ackTick()` for the game to send back, `apply(mirror, tick)` makes a mirror World match — same slots and generations via `World::spawnAt`, so Entity handles/fields agree — blending `interpolated` F32/Vec2 fields between the two snapshots around a fractional tick. What replicates: components with replicated fields (only those fields; Fixed16 quantized as round(v / scale), Varint zigzagged) and field-less tag components by presence; all-server-only components never hit the wire. A mirror world must not `spawn()` its own entities (they'd take the server's slots). Both sides need the same registry and prefabs (`ContentManifest` at join).
- `audio/` — `Audio` (miniaudio): named one-shots with N voices, one streamed music track; silent no-op if the device or file is missing.
- `net/`
  - `Transport` interface: message-oriented, `send(peer, bytes, Reliable|Unreliable)`, `poll()` → Data/Disconnected events, `pingMs`. No accept step — the game protocol decides who's in.
  - `UdpTransport`: plain UDP + minimal reliability (seq/ack/resend, in-order delivery), keepalive pings, 6s timeout. For LAN/localhost testing.
  - `SteamTransport`: ISteamNetworkingMessages (P2P with relay fallback); `acceptPeer` callback gates unsolicited sessions.
  - `SteamPlatform`: SteamAPI init, persona/SteamID, lobbies (create/join/leave/invite overlay/data), `+connect_lobby` parsing, event queue (incl. `JoinRequested` — the game decides whether to drop its session). Everything no-ops when Steam is absent or built with `-Dsteam=false`.
  - `ByteWriter` / `ByteReader`: little-endian, varints, int16 fixed-point. The reader is bounds-checked and latches `ok()` false — use it for all untrusted bytes.

## Gotchas

- **MinGW ABI + Steam** (zig's `windows-gnu` target is the MinGW ABI): Valve's `steam_api64.dll` is MSVC-built; OOP accessors that *return* `CSteamID` by value crash intermittently under MinGW. Use the flat API (`SteamAPI_ISteam*_*`, returns uint64) for anything returning a SteamID — see `SteamPlatform.cpp`.
- **Testing Windows builds under Wine:** use a fresh `WINEPREFIX`. A prefix made by an older Wine lacks `cryptbase.dll`, and the UCRT's `rand_s` then aborts on "unimplemented function advapi32.dll.SystemFunction036".
- Steam app id is Valve's test id 480 in each game's `steam_appid.txt` until real ones exist.
